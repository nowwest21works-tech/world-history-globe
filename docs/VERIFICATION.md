## 再照合の方法

作業環境からは ja.wikipedia.org へ直接接続できないため、Exa の Web 取得機能を経由した。前回までは同じ URL（api.php）に問い合わせを変えて送っていたため、別の記事の結果が返る取り違えが起こりえた。今回は**すべて記事ごとに URL が異なる問い合わせ**にした。

1. **存在確認**：全記事について REST API（`https://ja.wikipedia.org/api/rest_v1/page/summary/記事名`）を記事ごとに呼び、`type` が `standard`（通常の記事。曖昧さ回避ではない）であること、正規の記事名（`titles.canonical`）が出典に書いた記事名と一致すること（転送されていないこと）を確かめた。**全198本とも通常の記事で、転送・曖昧さ回避はなかった。**
2. **内容照合**：各イベントの主な出典記事を、記事ごとの URL（`https://ja.wikipedia.org/wiki/記事名`）で取得し、導入部・情報欄（記事右上の表）を読んだ。REST API の要約は導入部の最初の段落しか含まないため、照合には記事本体を使った。
3. **本文の確認**：導入部だけでは年代などを確かめられなかったもの（前回「判断不能」の35件など）は、記事本文の該当する節まで読んで判定し直した。下の表の「根拠の節」に、判定に使った節の名前を記録した。
4. 記事の本文は転載していない。表の「内容」は、照合結果を独自の文章で要約したもの。

## 判定の決まり

| 記号 | 意味 |
|---|---|
| ○ | 記事の記述と一致する（「頃」のイベントは、記事の年・幅と矛盾しなければ一致とした） |
| △ | 記事の記述と食い違う（記事内で記述が分かれ、本データが一方としか合わない場合を含む） |
| − | 読んだ範囲に該当する記載がなく、照合できない |

| 区分 | 基準 |
|---|---|
| 一致 | △がなく、年代が ○ |
| 要確認 | △が1つ以上ある（食い違いの内容を記載） |
| 判断不能 | △はないが、年代が −（本文まで読んでも主要な年を確かめられない） |

場所は、地名が記事に書かれていない場合が多いため、−があっても区分は下げていない。

優先度は次の順とした。(1) 戦争・虐殺・差別・テロなど、記述に特に配慮が必要なイベント（区分にかかわらず最優先）、(2) 要確認、(3) 再判定後も判断不能、(4) ツアー4本の語り文と問い。同じ優先度の中は、(1) は指定のあった4件を先頭にし、残りは影響の大きさの順、(2)(3) は年代順。

| 順番 | 対象 | 優先度 | 確認の観点 |
