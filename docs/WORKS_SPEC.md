# 作品から歴史へ ― エンタメ作品連携 実装指示書（第1段階）

作成：2026-11-05（設計担当：相棒Claude ／ 承認：今西）
実装担当：Claude Code
位置づけ：マホロバ学校の目玉コンテンツ。高校生が「知っている作品」から世界史に入り、地図と時系列で関連性に気づき、「作品と史実のあいだ」を問うことで探究を深める。

---

## 0. ゴール

1. **作品から入る**：「作品から探す」から作品を選ぶと、地球儀がその時代と地点へ移動し、紐づくイベントの詳細が開く。
2. **イベントから作品を見る**：イベント詳細に「この時代を描いた作品」を表示する。
3. **作品と史実の差分を問う**：各作品に「史実との距離」ラベルと、差分を問う問い（`gapQuestion`）を添える。

作品は**入口**であって**答え**ではない。UI の文言・並び順は、常に「史実のほうへ連れていく」向きに設計する。

---

## 1. 守ること（既存の運用ルールの延長）

- **画像を一切使わない。** 書影・ポスター・スチル・キャラクター画像は、引用の形であっても載せない（リポジトリは Public）。作品はテキスト（題名・作者・年・ラベル）で表す。
- **文章はすべて独自の文章。** 作品紹介文・あらすじ・キャッチコピーを公式サイトやウィキペディアから転載・言い換えしない。セリフや歌詞も引用しない。
- **URL は実在を確認したものだけ。** `officialUrl` は出版社・配給会社・放送局などの公式ページで、存在を確認できたときだけ入れる。確認できなければ空文字のまま。配信サービスへの直リンクはしない（配信状況はすぐ変わるため）。
- **出典**：作品の基本情報（作者・初出年など）の出典として、ウィキペディア日本語版の作品記事を `sources` に入れる。既存の `check:sources` と同じ方法（MediaWiki API）で記事の存在・曖昧さ回避でないことを確認する。
- **年齢への配慮**：`rating` には映倫区分・CERO などの**公式な区分を確認できた場合だけ**入れる（例：`"R15+"`、`"PG12"`）。推測では入れない。`contentNote` は描写の傾向の説明（独自文）。
- **`verified` はすべて `false`。** 人間が作品情報と紐づけを確認したものだけ `true` にする運用（イベントと同じ）。UI は既存の `UnverifiedBadge` を再利用する。
- `main` へは直接 push しない。ブランチで作業し PR を作る（マージは今西が判断）。

## 2. データ

### 2.1 型定義（新規 `src/types/work.ts`）

```ts
import type { AstroYear, SourceRef } from "./event";

/** 媒体 */
export type WorkMedia = "manga" | "anime" | "film" | "drama" | "novel" | "stage" | "game";

/**
 * 史実との距離
 * - historical：史実ベース（実在の人物・出来事が中心。演出上の脚色はある）
 * - historical-fiction：史実の枠に創作（史実の時代・事件を背景に、架空の人物や大胆な解釈を加える）
 * - inspired：時代を借りた創作（架空の国・時間移動・伝奇など）
 */
export type Fidelity = "historical" | "historical-fiction" | "inspired";

export interface HistoryWork {
  /** kebab-case・一意 */
  id: string;
  title: string;
  media: WorkMedia[];
  /** 作者・監督など表示用（独自の表記） */
  creators: string;
  /** 初出年（西暦。原作の連載開始・初公開など） */
  firstReleased: number;
  /** 主なメディア展開（表示用。空でよい） */
  adaptations: string;
  /** 作品が描く時代（天文学的年号） */
  era: { from: AstroYear; to: AstroYear };
  /** 時代についての補足（架空の国であること、諸説など） */
  eraNote: string;
  /** 舞台（独自の文章） */
  setting: string;
  /** 紐づくイベント（1件以上。events.json に存在すること） */
  eventIds: string[];
  fidelity: Fidelity;
  /** 作品を知っている人に向けた一言（独自の文章） */
  hook: string;
  /** 作品と史実の差分を問う探究の問い */
  gapQuestion: string;
  /** 描写についての注意（独自の文章。空でよい） */
  contentNote: string;
  /** 公式な年齢区分。確認できたときだけ。未確認は空文字 */
  rating: string;
  /** 公式ページ。実在を確認できたときだけ。未確認は空文字 */
  officialUrl: string;
  sources: SourceRef[];
  verified: boolean;
}
```

### 2.2 データファイル

- `src/data/works.json`：**シード36本（このブランチに同梱済み）**。既存イベント34件に紐づけてある。
  - `sources` は空。第1段階で、各作品のウィキペディア日本語版記事を確認して埋めること。
  - 作者名・初出年・メディア展開は相棒が下書きしたもの。**ウィキペディア記事と照合し、食い違いがあれば修正**して、修正内容を `docs/WORKS.md` の「照合記録」に残す。
  - `rating` / `officialUrl` は空。確認できたものだけ埋める。
- `src/data/works.ts`：`WORKS`（`firstReleased` ではなく `era.from` 順）と、イベントIDから作品を引く `worksByEventId(id)` を提供。

### 2.3 表示ラベル（`src/lib/works.ts`）

| 値 | 表示 |
|---|---|
| media: manga / anime / film / drama / novel / stage / game | 漫画 / アニメ / 映画 / ドラマ / 小説 / 舞台 / ゲーム |
| fidelity: historical | 史実ベース |
| fidelity: historical-fiction | 史実の枠に創作 |
| fidelity: inspired | 時代を借りた創作 |

ラベルの補足（ツールチップや凡例）は 2.1 の型コメントの説明文をそのまま使う。

### 2.4 整合性チェック（`src/lib/validate.ts` に `validateWorks(works, events)` を追加）

- id が kebab-case・一意
- title / creators / setting / hook / gapQuestion / eraNote が空でない
- media が1つ以上、すべて既定の値
- fidelity が既定の値
- `era.from`・`era.to` が整数で `to >= from`
- `firstReleased` が整数（1900〜今年）
- eventIds が1件以上・重複なし・すべて events.json に存在
- **時代のずれ**：各イベントの期間（start〜end）と作品の `era` が、重なるか、端どうしの差が50年以内
- `officialUrl` は空か `https://`
- `sources` の URL は空か `https://ja.wikipedia.org/wiki/`
- `rating` は空か、許可リスト（`G` / `PG12` / `R15+` / `R18+` / `CERO A`〜`CERO Z` など、実装時に定義）に含まれる
- **画像らしきフィールドを持たない**（`image` / `cover` / `thumbnail` などのキーがあればエラー）

## 3. 画面

### 3.1 入口：「作品から探す」

- ヘッダーの「歴史を旅する」ボタンの隣に **「作品から探す」** ボタン（`data-testid="works-open"`）。
- 押すとダイアログ（`TourMenu` と同じ作り：Esc で閉じる、背景クリックで閉じる、フォーカス管理）を開く。`data-testid="works-menu"`。
- ダイアログの中身：
  - 検索欄（題名・作者のあいまい一致。ひらがな／カタカナの違いは吸収できれば望ましい）
  - 媒体の絞り込み（チップ。複数選択可）
  - 一覧は**時代順**（`era.from` 昇順）。各カードに：題名／媒体ラベル／作者・初出年／描く時代（`formatYear` で「前○年〜○年」）／史実との距離ラベル／`hook`
  - カードを押す（`data-testid="work-start-<id>"`）と：
    1. ダイアログを閉じる
    2. 年代スライダーを、最初に紐づくイベントの開始年に合わせる
    3. そのイベントへカメラを移動し、詳細パネルを開く
    4. 詳細パネルの作品セクションで、選んだ作品を開いた状態・強調表示にする
- URL：`?work=<id>` で直接開ける（ツアーの `?tour=` と同じ扱い。両方あればツアーを優先）。作品を開いたら URL に反映し、閉じたら外す。

### 3.2 イベント詳細の「この時代を描いた作品」

- `EventDetail` の「歴史的な注記」と「出典」のあいだに、紐づく作品があるときだけセクションを出す。見出しは「この時代を描いた作品」（`data-testid="detail-works"`）。
- 各作品は折りたたみ（`<details>`）。閉じた状態：題名・媒体・史実との距離ラベル。開いた状態：
  - 作者・初出年・メディア展開
  - 描く時代と `eraNote`
  - 舞台（`setting`）
  - **「作品と史実のあいだ」**という見出しで `gapQuestion`（このセクションの主役。視覚的に目立たせる）
  - `contentNote` と `rating`（あれば）
  - 公式サイトへのリンク（`officialUrl` があるときだけ。外部リンクの表示）
  - 出典
  - 未検証バッジ
- ツアー中に詳細を開いた場合も同じ表示でよい。

### 3.3 マーカー

- 第1段階では地球上のマーカーは変えない。
- 年表表示（`ChronologyList`）では、作品が紐づくイベントに小さな「作品 n」表示を付ける（押すと詳細が開き、作品セクションが見える）。

### 3.4 文言の方針

- 「この作品は史実と違う」と断定する書き方はしない。違いは**問い**として示し、答えは出典・教科書へ向かわせる。
- 作品の評価（面白い・名作など）は書かない。

## 4. テスト

### 単体（vitest）
- `validateWorks(WORKS, EVENTS)` が空配列
- 件数 30〜200
- `verified` はすべて false
- 全作品の eventIds が実在
- `worksByEventId("qin-unification")` に `kingdom-hara` が含まれる
- fidelity 3種がすべて使われている

- 「作品から探す」→ キングダム → スライダーが前221年付近になり、詳細に「秦による中国統一」と作品セクションが出て、キングダムが開いている

- `npm run typecheck` / `npm test` / `npm run build` / `npm run test:e2e` がすべて通る

- `docs/WORKS.md`（作品データの運用ルール・照合記録・選定基準）を作成し、README に「作品から探す」の説明とリンクを追加
