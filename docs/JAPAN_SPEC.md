# 日本史モード 設計・実装指示書

World History Globe に「日本史モード」を足すための設計と、Claude Code への実装指示です。
前提として `README.md`、`docs/DESIGN.md`、`docs/WORKS_SPEC.md`、`docs/TOURS.md` を読んでから着手してください。

---

## 0. ねらい

- 高校の「日本史探究」の生徒が、**日本地図と年表**で日本史をたどれるようにする。
- いちばんの売りは **世界史との連動**。元寇・鉄砲伝来・石見銀山・開国のような場面で、日本地図と地球儀を行き来しながら「同じころ、世界では？」と「つながり」を体験できること。教科書が「日本史」「世界史」に分かれていることで見えにくくなっている関係を、画面上でつなぐ。
- 大事にするのは **正確さの網羅より、つながりを感じられること**。ただし、確認できない情報は推測で埋めない運用（出典の実在確認・`verified=false`・独自の文章）はそのまま守る。

## 1. 基本方針

1. **別アプリにしない。** 同じアプリ・同じリポジトリ・同じURLに「世界／日本」の切り替えを足す。イベント・ツアー・作品の仕組みは共有する。
2. **日本モードの地図は、日本周辺の平面地図（SVG）** にする。地球儀のズームでは、京都・奈良・大阪のような近い地点を見分けられず、地表の画像も粗くなるため。
3. **現代の県境・国境は描かない。** 世界史版の「現代の国境線を歴史的な国境として表示しない」方針と同じ。海岸線（陸と海）だけを描く。
4. **地図の範囲は、朝鮮半島と大陸の沿岸まで含める。** 白村江・元寇・朝鮮通信使・琉球・蝦夷地など、日本史の「外とのつながり」が地図の端で切れないようにする。目安は北緯24〜46度、東経122〜150度。琉球・北海道・樺太南部が入ること。
5. **地図タイルのサーバーを使わない。** オフラインでも動き、GitHub Pages の静的書き出しのままで済むように、地図データはリポジトリに同梱する。

## 2. 地図データ

- 第一候補は **Natural Earth の陸地データ（1:10m、パブリックドメイン）**。GitHub 上の配布（nvkelso/natural-earth-vector）から取得してよい。
- 日本周辺の範囲で切り出し、点を間引いて、軽いデータ（目安100KB以下）にしてから同梱する。切り出しと間引きは `scripts/` に再実行できるスクリプトとして残す。
- 投影と描画は d3-geo（ISCライセンス）を使ってよい。ほかのライブラリを入れる場合は、ライセンスを確認して README に記録する。
- 出典表記を画面の隅と README に入れる（「地図：Natural Earth」）。
- 採用しなかった候補と理由を README に短く残す（例：国土地理院の地図タイルは、現代の地名・境界が入ることとタイル配信に依存することから見送り）。

## 3. 画面と操作

### 3.1 モード切り替え
- ヘッダーに「🌏 世界」「🗾 日本」の切り替えを置く。URL は `?mode=japan`（省略時は世界）。既存の `?tour=`・`?work=`・イベント指定と組み合わせられること。
- **切り替えても年はそのまま引き継ぐ。** 引き継ぎ先の年代範囲の外なら、範囲の端に合わせる。
- 選んでいたイベントが切り替え先にも出るもの（3.4 の共有イベント）なら、選択も引き継ぐ。

### 3.2 日本地図
- ドラッグで移動、ピンチとホイールで拡大縮小。拡大の上限は、京都・奈良・大阪のマーカーが重ならずに見分けられる程度。
- マーカーの色・形・大きさは世界史版と同じ規則（分類6種の色とアイコン、importance による大きさ）。既存の `markerGroups` の考え方を流用し、近い地点がまとまるようにする。
- イベントを選ぶと、その地点へ滑らかに移動する。スマホでは世界史版と同じく、上に地図、下に詳細の2段にする。
- WebGL を使わない作りなので、WebGL 非対応の端末でも地図が出ること（年表リスト表示も引き続き使えること）。

### 3.3 年代スライダー
- 日本モードの範囲は **旧石器時代から現代まで**。目安として、始まりを前3万年頃とし、先史時代を強く圧縮する区分線形の目盛りにする（`src/lib/timeScale.ts` をモード別に持てる形にする）。
- 目盛りに時代区分（旧石器・縄文・弥生・古墳・飛鳥・奈良・平安・鎌倉・室町・安土桃山・江戸・明治・大正・昭和・平成・令和）を薄く添える。時代区分の境目は諸説あるため、`historicalNote` と同じ扱いで「目安」と明記する。
- 自動再生の挙動は世界史版と同じ。

### 3.4 世界史との連動（いちばん大事な部分）

**(a) 共有イベント（同じ出来事を二重に作らない）**
- `HistoryEvent` に任意の項目 `scopes: ("world" | "japan")[]` を足す。省略時は、`events.json` のものは `["world"]`、`events-japan.json` のものは `["japan"]` とみなす。
- 世界史データにすでにある日本の出来事（`heian-kyo`、`paper-east-asia`、`edo-sakoku`、`meiji-restoration`、`russo-japanese-war`、`atomic-bombings`）は、日本側に作り直さず `scopes` に `"japan"` を足して両方の地図に出す。
- 日本側の新しいイベントで世界史としても重要なもの（例：元寇）は、`scopes: ["japan", "world"]` にして地球儀にも出してよい。ただし世界史版の画面が日本のイベントで混み合わないよう、地球儀に出すものは importance 3 の数件に絞る。

**(b) 「世界とのつながり」セクション**
- イベント詳細に、`relatedEventIds` のうち **もう一方のモードにあるイベント** を「🌏 世界史で見る」「🗾 日本史で見る」のカードとして出す。押すと、モードを切り替え、その年・その地点へ移動し、詳細を開く。
- イベントIDは世界・日本を通して一意にする。日本側の新しいIDは `jp-` で始める（例：`jp-mongol-invasions`）。`relatedEventIds` は両方のデータをまたいで参照してよく、整合性チェックでは「どちらかに存在すること」を確かめる。

**(c) 「同じころ、世界では？」を日本モードにも**
- 日本モードの同時代リスト（`ContemporaryStrip`）に、**同じころの世界の出来事** を別の段として出す。押すと地球儀へ切り替えてそのイベントを開く。
- 世界モード側でも、同時代リストに日本の出来事が混ざるのではなく、「🗾 同じころ、日本では？」の段として分けて出す。

**(d) 地図の端の矢印**
- 日本地図で、選んだイベントが日本の外のイベントと `relatedEventIds` でつながっているとき、地図の端からその方角へ向かう矢印を出す（例：元寇なら大陸の方角、鉄砲伝来なら南西の海の方角）。矢印を押すと (b) と同じ動きをする。
- 第1段階で難しければ第2段階に回してよい。回した場合はその旨を報告する。

**(e) モードをまたぐツアー**
- `TourStep` に任意の項目 `mode?: "world" | "japan"`（省略時は世界）を足し、ツアーの途中でモードが切り替わるようにする。日本地図の上でのカメラ指定は、緯度・経度と拡大率で表す（`CameraPose` をモード別に解釈する）。
- 第1段階で、またぐツアーを2本作る。
  1. **「元寇――ユーラシアの嵐が博多湾へ」**（つながり型）：チンギス=カンのモンゴル統一 → 元の成立と大都 → 高麗（必要ならイベント追加）→ 文永の役・弘安の役（日本地図へ）→ 鎌倉幕府への影響。
  2. **既存ツアー「銀が世界をめぐる」に石見銀山を足す**：マニラ・ガレオンの前後に「石見銀山と灰吹法」を入れ、日本地図へ切り替わってから地球儀に戻る流れにする。日本の銀が世界の銀の流れの一部だったことが見えるようにする。
- 日本モードだけのツアーは第2段階以降でよい（候補：「1600年、日本では？ 世界では？」の同時代型、「鉄砲とキリスト教がやってきた」のつながり型）。

## 4. データ

### 4.1 ファイル
- `src/data/events-japan.json`：日本史イベント。型は既存の `HistoryEvent`（4.2の追加項目つき）。
- `src/data/units-japan.json`：日本史探究の単元構成。
- `docs/COVERAGE-JAPAN.md`：単元ごとの件数・目安・不足分の表（世界史の `COVERAGE.md` と同じ形）。`scripts/coverage-report.mjs` をモード別に出せるようにする。
- `docs/VERIFICATION-JAPAN.md`：出典照合の記録（`VERIFICATION.md` と同じ形）。

### 4.2 型の追加（すべて任意項目にして、既存データを壊さない）
- `HistoryEvent.scopes?: ("world" | "japan")[]`
- `HistoryEvent.era?: string`（日本モードの時代区分。例：「鎌倉」。表示と絞り込み用）
- `TourStep.mode?: "world" | "japan"`

### 4.3 イベント作成の決まり（世界史版と同じ）
- 出典は **ウィキペディア日本語版の記事URLのみ**。MediaWiki API で記事の存在と、曖昧さ回避・転送でないことを確認したものだけ載せる。`npm run check:sources` が日本側も確認するようにする。
- 概要・注記・問いは **独自の文章**。転載や言い換えはしない。
- `verified` はすべて `false`。照合結果は `docs/VERIFICATION-JAPAN.md` に追記する。
- 位置は、遺跡・城・寺社・港など地点がはっきりするものは `exact` か `city`、範囲の広い出来事は代表点を `region` で置き、注記に理由を書く。
- 年代の不確実性（「頃」「世紀」「±n年」）は既存の型で表す。旧石器・縄文の年代は諸説が大きいため、注記で必ず触れる。
- 1回の追加は20件以内のまとまりにし、まとまりごとにコミットする。

### 4.4 単元の基準
- **文部科学省の高等学校学習指導要領（平成30年告示）「日本史探究」の大項目・中項目** を基準にする（A 原始・古代、B 中世、C 近世、D 近現代）。学習指導要領の文章は転載せず、単元名と自分の言葉での要約にとどめる。
- 全単元が最低件数を満たした状態を「日本史の骨格の完成」とし、合計の目安を示す（120〜150件程度を想定）。

## 6. 作品連携（日本史）

- 既存の作品データ（`works.json`）で日本が舞台のもの（『阿・吽』『沈黙』『坂の上の雲』『ゴールデンカムイ』『この世界の片隅に』『はだしのゲン』）は、日本側のイベントにも紐づけ直す。
- 新しい日本史の作品は **第2段階**（PR③）で入れる。使い手である高校生の声を候補に反映するため、今西から候補が届くのを待つ。第1段階では作品データを新しく作らない。
- 候補の下書き（照合前・確定ではない）：大河ドラマ（『光る君へ』『鎌倉殿の13人』『麒麟がくる』『どうする家康』『べらぼう』など）、漫画・アニメ（『逃げ上手の若君』『アンゴルモア 元寇合戦記』『へうげもの』『センゴク』『風雲児たち』『あさきゆめみし』『天地明察』『はいからさんが通る』『鬼滅の刃』『るろうに剣心』など）。時代を借りた創作は `fidelity: "inspired"` とする。
- **PR③（第1弾）で入れた作品**：今西の優先順位で、大河ドラマ『龍馬伝』『真田丸』『鎌倉殿の13人』の3作（2026-11-06）。紐づけの根拠・追加した錨のイベント6件・世界モードでの扱いは [WORKS.md](WORKS.md) の5章と [VERIFICATION-JAPAN.md](VERIFICATION-JAPAN.md) の第7回。

## 7. 進め方と提出物

作業ブランチは `feature/japan-mode`（この指示書が入っているブランチ）。強制プッシュは使わない。マージはしない（マージと公開は今西のGOで行う）。

**PR①：日本モードの土台と世界史との連動（作業ブランチ → main）**
1. 地図データの切り出しスクリプトと同梱データ、日本地図の表示、モード切り替え、年代スライダーのモード別目盛り
2. 型の追加（4.2）と、データ読み込み・整合性チェックの日本対応
3. 第5章の候補から、**世界史とつなぐ橋（太字）を優先して最初の20件**
4. 世界との連動 (a)(b)(c)、できれば (d)
5. またぐツアー2本（3.4 (e)）
6. テスト：単体（年代目盛り、モード切り替え時の年の引き継ぎ、ID の一意性と両データをまたぐ参照、共有イベントの表示）と操作テスト（日本モードへの切り替え、`?mode=japan` での直接表示、世界↔日本のカードでの往復、またぐツアーの最後まで、スマホ幅390pxで上に地図・下に詳細）
7. `npm run typecheck` / `npm test` / `npm run build` / `npm run test:e2e` がすべて通ること

**PR②：日本史イベントの追加と単元カバー表（PR①の上に積む）**
1. `units-japan.json` と `docs/COVERAGE-JAPAN.md`
2. 第5章の残り（目安40件）を20件以内のまとまりで追加し、照合記録を残す
3. 日本だけのツアー1本（候補：「1600年、日本では？ 世界では？」）

PR②を作ったら止めて、日本語で次を報告する。
- PR①・PR②の URL とマージの順番
- テスト結果
- カバー表の要約（単元ごとの件数）
- 追加したイベントの一覧（すべて `verified=false`）
- 第2段階に回したもの、確認できなかった項目
- 画面のスクリーンショット（PC・スマホそれぞれ、日本モードと、元寇ツアーで世界から日本へ切り替わる場面）
